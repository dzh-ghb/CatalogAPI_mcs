# Mediator

Реализация паттерна **Mediator**, заменяющая необходимую часть функциональности MediatR.

### Зачем нужна

Посредник принимает команды/запросы от вызывающего кода, находит соответствующий обработчик и передаёт ему запрос.

Дополнительно поддерживается **pipeline behaviors**: общая сквозная логика, которая выполняется до/после обработчика, например валидация, логирование или таймауты.

Упрощённо:

`Endpoint → Sender → Pipeline Behaviors → Handler`

## Файлы

| Файл                              | Назначение                                                                                                                 |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `IRequest.cs`                     | Маркерный интерфейс запроса. Связывает тип запроса с типом его ответа.                                                     |
| `IRequestHandler.cs`              | Контракт обработчика. Определяет метод `Handle`, который получает запрос и возвращает результат.                           |
| `ISender.cs`                      | Контракт посредника. Определяет метод `Send`, через который запрос передаётся посреднику.                                  |
| `Sender.cs`                       | Основная реализация посредника. Находит нужный обработчик через DI и запускает pipeline.                                   |
| `IPipelineBehavior.cs`            | Контракт отдельного звена pipeline. Позволяет выполнять общую логику и передавать запрос следующему звену.                 |
| `RequestHandlerDelegate.cs`       | Делегат, представляющий следующий шаг pipeline. В конечном итоге приводит к вызову обработчика.                            |
| `MediatorConfigurations.cs`       | Хранит настройки библиотеки: сборки, в которых искать обработчики, и зарегистрированные behaviors.                         |
| `ServiceCollectionsExtensions.cs` | Метод расширения `AddMediator`. Регистрирует библиотеку в DI, ищет обработчики в указанных сборках и подключает behaviors. |
| `Unit.cs`                         | Тип-заглушка вместо `void`, когда запрос формально должен иметь тип ответа, но фактически ничего не возвращает.            |

## Общая схема

```text
Запрос
  ↓
ISender / Sender
  ↓
Pipeline Behaviors
  ↓
IRequestHandler
  ↓
Ответ
```

`IRequest` и `IRequestHandler` задают контракты, `Sender` связывает запрос с обработчиком, а `IPipelineBehavior` позволяет добавлять общую логику в цепочку обработки.
